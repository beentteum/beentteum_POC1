# 0. Coding Test - Lv.0

## 배열의 평균값

### 문제 설명

정수 배열 `numbers`가 주어질 때,
배열에 포함된 값들의 평균을 계산하여 반환한다.

### Requirements

- 정수 배열을 입력받는다.
- 배열의 모든 값을 더한다.
- 합계를 배열의 길이로 나누어 평균을 계산한다.
- 계산된 평균값을 반환한다.

### 입력값

- `numbers`: 정수로 구성된 배열

### 출력값

- 배열에 포함된 숫자들의 평균값

### 풀이 Flow

```text
numbers 입력
    ↓
배열의 모든 값 합산
    ↓
합계 ÷ 배열 길이
    ↓
평균값 반환
```

### Business Logic

1. 합계를 저장할 변수 `sum`을 생성한다.
2. 반복문을 사용하여 배열의 모든 숫자를 더한다.
3. `sum`을 배열의 길이로 나눈다.
4. 소수점 결과를 반환할 수 있도록 `double` 타입으로 계산한다.
5. 평균값을 반환한다.

### Code

```java
public double solution(int[] numbers) {
    int sum = 0;

    for (int number : numbers) {
        sum += number;
    }

    return (double) sum / numbers.length;
}
```

### Test Case

```java
int[] numbers = {1, 2, 3, 4, 5};
System.out.println(solution(numbers));
```

결과

```text
3.0
```

### 핵심 포인트

배열을 순회하면서 값을 누적하고,
합계를 배열의 길이로 나누어 평균값을 구하는 기본적인 반복문과 형 변환을 이해한다.

# 1. PoC 기능 개발

## 혼잡도 제보 등록

## 1. Requirements

사용자가 방문한 카페의 현재 혼잡도를 제보할 수 있다.

실제 서비스에서는 QR 인증과 위치 확인을 거쳐 현장 사용자인지 확인하지만,
이번 PoC에서는 현장 인증이 완료된 사용자라는 상황을 전제로
혼잡도 제보 등록 비즈니스 로직을 구현한다.

### 요구사항

- 사용자는 특정 카페의 현재 혼잡도를 제보할 수 있다.
- 제보를 위해 사용자 ID, 카페 ID, 혼잡도 정보가 필요하다.
- 혼잡도는 `여유`, `보통`, `혼잡` 중 하나여야 한다.
- 동일 사용자는 동일 카페에 60분 이내 다시 제보할 수 없다.
- 60분 이내 중복 제보인 경우 새로운 제보 데이터를 저장하지 않는다.
- 정상적인 제보는 저장 후 성공 결과를 반환한다.

### 입력값

- `userId`: 혼잡도를 제보하는 사용자 ID
- `cafeId`: 제보 대상 카페 ID
- `crowdLevel`: 현재 혼잡도

### 허용 혼잡도

- `여유`
- `보통`
- `혼잡`

### 결과

정상 등록

```text
혼잡도 제보 등록 완료
```

60분 이내 중복 제보

```text
이미 최근에 혼잡도를 제보한 카페입니다.
```

잘못된 혼잡도 값

```text
유효하지 않은 혼잡도입니다.
```

## 2. User Flow

```text
사용자가 카페 혼잡도 제보
        ↓
userId, cafeId, crowdLevel 입력
        ↓
필수 입력값 확인
        ↓
crowdLevel이 유효한가?
        ↓
 ┌──────┴──────┐
아니오          예
 ↓              ↓
등록 실패    최근 제보 확인
                ↓
       동일 사용자 + 동일 카페
       60분 이내 제보가 있는가?
                ↓
          ┌─────┴─────┐
          예           아니오
          ↓              ↓
     중복 등록 안 함    제보 등록
          ↓              ↓
     중복 결과 반환    등록 완료 반환
```

### Exception

- 필수 입력값 누락 → 제보 등록 실패
- 허용되지 않은 `crowdLevel` → 제보 등록 실패
- 동일 `userId + cafeId` 조합으로 60분 이내 재제보 → 중복 등록하지 않음
- 60분 이내 중복 제보 → HTTP `409 Conflict`

---

## 3. Business Logic

1. `userId`, `cafeId`, `crowdLevel`을 입력받는다.
2. 필수 입력값이 존재하는지 확인한다.
3. `crowdLevel`이 `여유`, `보통`, `혼잡` 중 하나인지 확인한다.
4. 동일한 사용자가 동일 카페에 등록한 최근 제보를 조회한다.
5. 최근 제보가 현재 시점을 기준으로 60분 이내인지 확인한다.
6. 60분 이내 제보가 존재하면 새로운 제보를 등록하지 않는다.
7. 중복 제보인 경우 `409 Conflict` 결과를 반환한다.
8. 중복 제보가 아니라면 새로운 혼잡도 제보를 저장한다.
9. 정상 저장되면 `혼잡도 제보 등록 완료` 결과를 반환한다.

### 로직 요약

```text
userId, cafeId, crowdLevel 입력
              ↓
         입력값 검증
              ↓
        혼잡도 값 검증
              ↓
  동일 사용자 + 동일 카페
       최근 제보 조회
              ↓
        60분 이내인가?
         ┌────┴────┐
         예        아니오
         ↓           ↓
      등록 안 함    제보 등록
         ↓           ↓
   409 Conflict    등록 완료
```
